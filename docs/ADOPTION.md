# 다른 기관에서 서무비서 쓰기 — 도입 가이드

서무비서는 **기관 설정 · 우리 기관 내규 · 절차** 세 가지만 바꾸면 어느 공공기관에서도 쓸 수 있게 만들어져 있습니다.
코드 수정은 필요 없습니다.

| 바꿀 것 | 위치 | 방법 |
|---|---|---|
| 기관 이름·서비스 이름·색·명칭·기관 휴일 | `secretary/config.json` | 화면 **⚙ 규정·절차 관리 › 🏢 기관 설정**, 또는 파일 직접 수정 |
| 우리 기관 내규(원문·서식) | `regulations/`, `regulations_manifest.json` | `scripts/import_regs.py`로 일괄 등록, 이후 개정은 `/upload` |
| 절차가 가리키는 규정명 ↔ 우리 규정 | `config.json`의 `reg_aliases` | 화면 **🔗 규정명 매핑** |
| 우리 기관 고유 절차 | `secretary/org.json` | 화면에서 '기관'으로 저장, 또는 **📦 절차 팩** 가져오기 |

---

## 1. 설치

**Vercel**(가장 간단)
1. 이 저장소를 기관 GitHub로 포크합니다.
2. Vercel에서 저장소를 가져오면 `vercel.json` 설정대로 바로 배포됩니다.
3. 환경변수 `REG_UPLOAD_TOKEN`(관리자 토큰)과 `GITHUB_TOKEN`·`GITHUB_REPO`를 등록합니다. 읽기 전용 배포에서는 화면에서 저장한 내용이 저장소 커밋으로 반영됩니다.

**기관 내부 서버(온프레미스)**
```bash
docker build -t secretary .
docker run -d -p 8000:8000 --env-file .env \
  -v $(pwd)/regulations:/app/regulations \
  -v $(pwd)/regulations_manifest.json:/app/regulations_manifest.json \
  -v $(pwd)/secretary:/app/secretary secretary
```
- 볼륨을 붙이면 화면에서 올린 내규·절차·설정이 컨테이너를 다시 만들어도 남습니다.
- 내부망에서는 `GITHUB_*` 없이 로컬 파일에 저장됩니다.
- Docker 없이 실행하려면 `pip install -r requirements.txt` 후 `python run_local.py`를 실행합니다.

환경변수 전체 목록: `.env.example`

## 2. 기관 설정

화면 **⚙ 규정·절차 관리 › 🏢 기관 설정**에서 저장하거나, `secretary/config.json`을 고칩니다(형식: `secretary/schema/config.schema.json`).

```json
{
 "org": {"name": "○○공단", "short": "OO", "abbr": "○○공단"},
 "service": {"title": "서무비서", "icon": "🗂", "primary": "#0f766e", "tagline": "…", "footer": "…"},
 "terms": {"erp": "통합정보시스템", "portal": "그룹웨어", "accounting": "재무팀", "approval": "전자결재"},
 "reg_aliases": {"여비규정": "○○공단 여비 지급 규정"},
 "holidays": {"extra": [{"date": "2026-05-01", "name": "근로자의 날"}], "exclude": []}
}
```
- **terms**: 절차 문장 속 `[[erp]]`·`[[portal]]`·`[[accounting]]`·`[[approval]]`이 이 명칭으로 바뀝니다. 예를 들어 "[[erp]]에서 지출결의"는 "통합정보시스템에서 지출결의"로 표시됩니다.
- **holidays**: 법정 공휴일·대체공휴일은 `secretary/holidays.json`에 기본으로 들어 있습니다. 창립기념일처럼 기관에만 있는 휴일은 `extra`에 적고, 연도가 바뀌면 `holidays.json`에 새 해를 덧붙입니다.

## 3. 우리 기관 내규 등록

```bash
python scripts/import_regs.py ./우리기관_내규 --dry-run   # 목록 확인
python scripts/import_regs.py ./우리기관_내규 --reset     # 기존(KOAT) 내규를 비우고 우리 내규로 새로 등록
```
- 파일명 규칙은 `규정명(개정 정보).hwpx`입니다. 예: `여비 지급 규정(2025년도 3월 일부개정).hwpx`
- 지원 형식은 hwpx·docx·html·txt·pdf입니다. 한글 `.hwp`는 한글에서 `.hwpx`로 저장한 뒤 올립니다.
- 별표·별지 서식은 원문에서 자동으로 찾아 **서식·규정** 탭과 절차의 📎 서식 버튼에 연결됩니다.
- 관련 조문 찾기에 의미 검색을 쓰려면 `GEMINI_API_KEY`를 설정하고 `python scripts/build_embeddings.py`를 실행합니다. 의미 검색이 없어도 키워드 검색으로 동작합니다.
- 등록이 끝나면 `git commit`·`push`로 배포본에 반영합니다. 그 뒤의 개정은 화면 `/upload`에서 한 건씩 올리면 됩니다.

## 4. 절차를 우리 규정에 연결 — 규정명 매핑

기본 탑재 절차 14종은 한국농업기술진흥원 규정명(예: 「여비규정」 제8조)으로 근거를 가리킵니다. 우리 기관 규정과는 아래 순서로 자동 연결합니다.

1. **매핑**(`reg_aliases`)에 적힌 규정
2. **정확히 같은 이름**
3. **기관명 접두어**를 붙이거나 뗀 이름. 예: "여비규정"과 "○○공단 여비규정"
4. **근사 연결**: 이름이 서로 포함되거나 어간이 같은 규정. 예: "여비규정"과 "여비 지급 규정". 틀릴 수 있어 '확인 필요'로 표시합니다.

화면 **🔗 규정명 매핑**에는 절차가 참조하는 규정명마다 어디에 연결됐는지(정확·매핑·접두어·근사·연결 안 됨)가 표시됩니다. 드롭다운에서 우리 규정을 골라 **매핑 저장**을 누르면 됩니다.

**🩺 호환성 점검**에서는 절차별로 다음을 확인할 수 있습니다.
- 🔗 연결 안 된 근거·서식: 규정이 없거나, 그 조문·별지가 없는 경우
- 📝 근거 규정 개정: 같은 규정이 확인 이후 개정된 경우
- 우리 기관 규정으로 확인 전: 다른 기관·다른 이름의 규정 기준으로 만들어진 절차

조문 번호가 우리 규정과 다르면(예: 정산 기한이 제8조가 아니라 제10조), 그 절차를 **수정**해 근거를 고친 뒤 '기관'으로 저장합니다. 우리 기관에 없는 업무라면 **숨기기**합니다.

## 5. 절차 확인과 개정 관리

- 기관 층으로 저장하면 그 시점의 근거 규정 개정 정보가 절차에 기록됩니다(`verified`). 어느 규정과 대조했는지도 함께 남습니다.
- 이후 그 규정이 `/upload`로 개정되면 해당 절차 화면과 호환성 점검에 **"근거 규정이 개정되었습니다 — 재확인 필요"**가 뜹니다. 원문과 대조한 뒤 다시 저장하면 알림이 사라집니다.
- 공통 절차 파일을 직접 고쳤다면 `python scripts/stamp_procedures.py`로 개정 정보를 다시 기록합니다. `--check`를 붙이면 기록 없이 점검만 하고, 문제가 있으면 종료코드 1을 돌려줘 CI에 넣을 수 있습니다.

## 6. 기관 간 절차 공유 — 절차 팩

**📦 절차 팩**으로 기관·부서끼리 절차를 주고받을 수 있습니다(형식: `secretary/schema/procedures.schema.json`, `kind: "secretary-pack"`).

- **내보내기**: 보이는 절차 전체·기관 층·개인 층 중 고릅니다. 절차·초안 서식과, 참조한 규정의 이름·개정 정보가 함께 담깁니다.
- **가져오기**: 저장하기 전에 우리 규정에 몇 개가 그대로 연결되는지 미리 보여 줍니다. 그다음 개인 층이나 기관 층(관리자)에 추가하고 **규정명 매핑**으로 마무리합니다.

절차 파일 직접 작성 요령:
- 근거는 `{"reg":"규정명","art":"8"}` 형식으로 적습니다. 조문 번호가 없는 지침은 `{"reg":"규정명","q":"찾을 말"}`로 적습니다.
- 서식은 `{"reg":"규정명","label":"별지 제5호 서식"}` 형식입니다.
- 기한은 `{"ref":"end","days":14}` 형식입니다. 기준일 키는 절차의 `dates`에 정의하고, 음수는 그 날짜 전을 뜻합니다.
- 기관마다 다른 명칭은 `[[erp]]`처럼 자리표시로 씁니다.
- 반려 점검 항목은 `pitfalls`에 적습니다.

## 7. AI 비서 기능(선택)

| 기능 | 키가 있을 때 | 키가 없을 때 |
|---|---|---|
| 영수증 사진 인식 | 날짜·금액·가맹점·종류를 자동으로 읽음 | 사진을 붙이고 직접 입력(증빙 점검은 그대로 동작) |
| 상황 이해 | 등록 절차에 없는 표현·섞인 문장을 해석 | 등록 절차의 '이런 말에 반응' 단어로 매칭 |
| 결재 전 사전 감사 | 규칙 감사 + AI 감사관이 근거 조문과 대조 | 규칙 감사(기한·숙박비 상한·증빙·초안 필수 항목) |
| 규정 개정 영향 분석 | 자동 제안 + 단계 문장 갱신안 | 자동 제안(조문 번호 이동·기한 일수) |

- `ANTHROPIC_API_KEY`(Claude) 또는 `GEMINI_API_KEY`(Gemini)를 설정합니다. 둘 다 있으면 Claude를 씁니다.
- 공급자를 고정하려면 `SECRETARY_AI_PROVIDER`를 쓰고, 모델을 바꾸려면 `SECRETARY_AI_MODEL`을 씁니다.
- AI는 **등록된 절차 목록 안에서만** 고르고, 규정·기한은 항상 절차 데이터와 내규 원문에서 나옵니다. 영수증에서 읽은 값은 화면에서 사람이 확인·수정합니다.
- 영수증 사진은 서버에 저장하지 않고 AI 분석에만 씁니다. 기관 보안 정책상 외부 AI 전송이 어려우면 키를 설정하지 않으면 됩니다. 나머지 기능은 모두 그대로 동작합니다.
- 공개 주소에서 기관 키가 남용되지 않도록 IP당 요청 한도(`SECRETARY_AI_RATE`, 기본 10분 40회)를 둡니다. 내부망 배포를 권장합니다.
- 한글 초안의 기본 서식은 내장 최소 서식입니다. 기관 공문 서식(.hwpx)을 `secretary/template.hwpx`로 두면 그 쪽 설정·글꼴을 씁니다.

## 7-1. 결재 전 사전 감사 기준

규칙 감사의 기본값은 KOAT 「여비업무 처리지침」·「여비규정」·「법인카드 운영요령」 기준입니다. 우리 기관 기준이 다르면 `config.json`에 `audit`를 적습니다(적지 않은 항목은 기본값). 화면에서 기관 설정을 저장해도 이 값은 그대로 남습니다.

```json
"audit": {
 "lodging_caps": [{"name": "서울특별시", "cap": 100000}, {"name": "광역시", "cap": 80000}, {"name": "그 밖의 지역", "cap": 70000}],
 "lodging_extra_ratio": 0.3,
 "lodging_basis": [{"reg": "여비 지급 규정", "art": "12"}],
 "card_basis": {"reg": "여비 지급 규정", "art": "6"},
 "trip_procs": ["domestic-trip", "training"],
 "draft_required": {"card-evidence": {"fields": ["purpose", "date", "place", "reason", "target"], "basis": {"reg": "법인카드 사용 지침", "art": "9"}}}
}
```
- 숙박 영수증마다 **숙박 지역**을 고르면 그 지역 상한으로, 고르지 않으면 가장 높은·낮은 상한과 비교해 알려 줍니다.
- AI 감사관은 절차의 근거 조문 원문만 받아 대조하고, 지적마다 그 목록 안에서 근거를 고릅니다. 근거를 대지 못한 지적은 '참고'로 낮춥니다.

## 7-2. 규정 개정 영향 분석

- `/upload`로 개정본을 올리면 이전본이 보관되고(로컬: `regulations/.backup/`, GitHub 연동: 개정 직전 커밋), **⚙ 규정·절차 관리 › 🔬 규정 개정 영향 분석**에 그 규정이 나타납니다. 절차 화면의 '근거 규정이 개정되었습니다' 알림에서도 바로 열 수 있습니다.
- 조문 번호 이동(조문 신설·삭제로 밀린 번호), 기한 일수 변경, 조문 삭제를 찾아 고칠 안을 만듭니다. 관리자가 골라 저장하면 기관 층에 반영되고 그 개정을 확인한 것으로 기록됩니다.
- `import_regs.py`로 일괄 교체한 규정은 이전본이 보관되지 않아 비교할 수 없습니다. 이후 개정은 `/upload`로 올리세요.

## 7-3. 기관 집단 지식

- 내부 서버(Docker 등 쓰기 가능한 서버)는 설정 없이 `secretary/insights.json`에 쌓입니다. 볼륨에 `secretary/`를 붙여 두세요.
- Vercel처럼 읽기 전용 배포는 Upstash Redis(Vercel Marketplace의 KV)를 연결하면 켜집니다(`UPSTASH_REDIS_REST_URL`·`UPSTASH_REDIS_REST_TOKEN` 또는 `KV_REST_API_URL`·`KV_REST_API_TOKEN`). 저장소가 없으면 기능이 꺼지고 나머지는 그대로 동작합니다.
- `config.json`의 `"insights": {"enabled": false}`로 끄고, `"min_n": 5`처럼 통계를 보일 최소 표본을 올릴 수 있습니다(기본 3).
- 공유된 반려 사유는 **👥 기관 집단 지식** 카드에서 관리자가 **점검 항목으로** 올리거나 **삭제**합니다.

| 데이터 | 저장 위치 | 공유 범위 |
|---|---|---|
| 공통 절차·기관 절차·기관 설정·내규 | 서버(저장소) | 모든 사용자 |
| 처리 이력·개인 보충 메모·개인 절차·반려 기록·영수증 미리보기 | 각자의 브라우저(localStorage) | 본인만 — 서버로 보내지 않음 |

| 집단 지식: 완료 건의 처리 일수·기한 넘긴 단계 번호·감사 항목 종류(익명 숫자), 담당자가 공유를 고른 반려 사유(이름·전화번호·금액 제거) | 서버(insights.json 또는 Redis) | 모든 사용자(통계는 표본 3건 이상일 때) — 처리 이력 화면에서 끌 수 있음 |

담당자가 바뀌면 **처리 이력 › 내보내기**로 넘겨줍니다. 반려 기록도 함께 넘어갑니다.

## 9. 도입 점검표

- [ ] `REG_UPLOAD_TOKEN` 설정, 관리자에게만 공유
- [ ] 기관 설정: 기관명·서비스 이름·색·명칭·기관 휴일
- [ ] `import_regs.py --reset`으로 우리 내규 등록 → 배포
- [ ] 규정명 매핑: '연결 안 됨'·'근사' 0건

- [ ] 우리 기관 고유 업무 절차 추가(또는 다른 기관 절차 팩 가져오기)
