# 🗂 KOAT 서무비서

**한국농업기술진흥원(KOAT) 서무 업무를 돕는 비서형 웹 서비스**입니다.
출장·물품·행사·복무·결재 같은 서무 규정·지침·서식을 담아 두고, 담당자가 **상황을 말하면**
절차 확인 → 할 일·기한 안내 → 필요한 서식과 문서 초안 준비까지 한 화면에서 해 줍니다.

> 브라우저만 있으면 됩니다. 설치나 회원가입 없이 PC와 휴대폰에서 모두 쓸 수 있습니다.

## 왜 필요한가
- 출장·물품·행사·복무·결재 등 서무는 종류마다 절차·서식·규정·기한이 다른데, 매뉴얼은 문서로 흩어져 있어 찾아 읽기 어렵고 실제 순서는 전임자에게 물어 배우는 경우가 많습니다.
- 서무 담당은 자주 바뀌고 대부분 겸임이라 같은 시행착오와 반려가 반복됩니다.

## 주요 기능

### 기본기능
| 기능 | 내용 |
|---|---|
| **상황으로 묻기** | "출장 다녀와서 정산해야 해요", "노트북 2대 사야 해요"처럼 입력하면 해당 절차를 찾습니다. 등록된 절차가 없으면 관련 규정 조문을 대신 보여 줍니다. |
| **업무별 절차 정리** | 단계마다 순서·시점·기한·필요 서류·결재선을 정리해 보여 줍니다. |
| **근거 확인** | 단계마다 📖 근거 조문을 펼치면 현행 내규 원문에서 해당 조문을 바로 불러옵니다. **전문에서 보기**를 누르면 원문이 열리고 그 조문으로 이동합니다. |
| **서식 찾기** | 📎 서식을 누르면 규정 원본의 해당 별지·별표 위치가 바로 열립니다. **서식·규정** 탭에서 627종 서식과 규정 원문을 검색할 수 있습니다. |
| **규정·서식 수정·삭제·추가** | 절차를 **공통 → 기관 → 개인 보충** 세 층으로 관리합니다(아래 '절차 관리'). 내규 원문은 `/upload`에서 개정·신규 등록합니다. |

### 선택기능
| 기능 | 내용 |
|---|---|
| **문서 초안** | 출장결과보고서·여비 정산·국외출장 귀국보고서·휴가 신청·물품 청구·법인카드 증빙·업무 인계 목록·기안문 본문·외부강의 신청. 입력하면 미리보기가 채워지고 복사하거나 텍스트로 저장합니다. |
| **다음 할 일·기한** | 출발일·마친 날 같은 기준일을 넣으면 "마친 날 다음 날부터 14일 이내" 같은 기한을 날짜와 D-day로 계산하고 다음 할 일을 짚어 줍니다. 기한은 **캘린더 파일(.ics)**로 받아 Outlook·구글 캘린더에 넣을 수 있습니다. |
| **결재선 정리** | 위임전결규칙 별표의 해당 항목을 안내하고, 부서에서 실제로 쓰는 결재선은 **개인 보충**에 적어 두면 절차를 열 때마다 함께 보입니다. |
| **층별 관리** | 공통 규정(기본 탑재) · 기관 규정(관리자 등록) · 개인 보충(내 브라우저)을 따로 관리합니다. |
| **처리 이력** | 체크한 단계·기준일·메모가 건별로 남습니다. 담당자가 바뀌면 이력 파일을 내보내 넘겨줄 수 있습니다. |

### 서무비서만의 기능
| 기능 | 내용 |
|---|---|
| **🗓 문장 속 날짜 인식** | "10월 5일부터 7일까지 출장 다녀왔어요", "어제", "다음 주 화요일", "10/5~10/7", "2박 3일"을 읽어 기준일을 자동으로 넣고 기한을 바로 계산합니다. |
| **⚠ 휴일 기한 보정** | 계산된 기한이 토·일·공휴일(대체공휴일·기관 휴일 포함)이면 앞 근무일을 함께 안내합니다. |
| **🚫 제출 전 반려 점검** | 절차마다 규정 조문에 근거한 '반려되기 쉬운 항목'을 결재 전에 확인합니다. 실제로 반려됐다면 **반려 사례 기록**을 남겨 다음 처리 때 점검 항목으로 보이게 하고, 관리자는 이를 기관 점검 항목으로 올립니다. 점검이 남은 채 완료하면 한 번 더 확인합니다. |
| **📝 근거 개정 감지** | 각 절차는 근거 규정의 확인 당시 개정 정보를 기억합니다. 규정이 개정·재업로드되면 해당 절차에 "근거 규정이 개정되었습니다 — 재확인 필요"를 표시합니다. |
| **⏰ 기한 경과 경고** | 기한이 지난 미완료 단계가 있으면 알려 줍니다. |

### 다른 기관에서 쓰기(호환성)
코드 수정 없이 **기관 설정 · 우리 내규 · 규정명 매핑**만으로 도입합니다. 자세한 순서는 [docs/ADOPTION.md](docs/ADOPTION.md)를 보세요.
- **기관 설정**(`secretary/config.json`, 화면에서 편집): 기관명·서비스 이름·대표 색·아이콘, 절차 문장의 기관별 명칭(`[[erp]]`→"통합정보시스템" 등), 기관 휴일
- **규정명 매핑**: 절차가 가리키는 규정명을 우리 기관 규정에 연결합니다(매핑 → 정확 일치 → 기관명 접두어 → 근사 연결 순으로 자동 연결, 근사는 '확인 필요' 표시).
- **🩺 호환성 점검**: 연결 안 된 근거·서식, 근거 규정 개정, 우리 규정으로 확인 전인 절차를 한눈에 보여 줍니다.
- **📦 절차 팩**: 절차를 표준 JSON(`secretary/schema/`)으로 내보내고 가져옵니다. 가져오기 전에 우리 규정 연결 여부를 미리 보여 줍니다.
- **일괄 등록·배포**: `scripts/import_regs.py`(내규 폴더 일괄 등록), `Dockerfile`(기관 내부 서버), `.env.example`

## 빠른 사용법
1. 첫 화면 입력창에 **상황을 문장으로** 적고 **안내받기**를 누릅니다(예시 문구를 눌러도 됩니다).
2. 절차 화면에서 **기준일**을 넣으면 단계별 기한과 **다음 할 일**이 계산됩니다.
3. 단계마다 **📖 근거**, **📎 서식**, **📝 초안 작성**을 눌러 필요한 것을 바로 준비합니다.
4. 결재 올리기 전 **🚫 제출 전 반려 점검**을 확인합니다.
5. 마친 단계를 체크하면 **처리 이력**에 저장됩니다. 남은 기한은 **📅 기한 캘린더(.ics)**로 받습니다.

> 💡 "10월 5일부터 7일까지 출장 다녀왔어요"처럼 **날짜를 함께 말하면** 기준일이 자동으로 들어갑니다.

바로가기 주소: `/?q=상황` (바로 안내) · `/?reg=규정명` (원문 열기) · `/?view=forms|history|manage`

## 개인정보와 데이터 저장
- **처리 이력, 개인 보충(메모·개인 절차·반려 기록)**은 **사용 중인 브라우저에만** 저장되고 서버로 보내지 않습니다. 브라우저 데이터를 지우거나 다른 PC를 쓰면 보이지 않으니 처리 이력의 **⬇ 내보내기**로 보관하세요.
- **기관 절차**는 관리자가 저장하면 서버(저장소)에 기록되어 모든 사용자에게 보입니다.

> 본 서비스는 업무 참고용입니다. 최종 판단은 기관 규정 원문과 담당 부서 확인을 거쳐 주세요.

## 관리자 안내

### 기술 구성
- **프론트엔드**: `index.html`(화면 틀) + `assets/secretary.js`·`assets/secretary.css`(서무비서). 빌드 과정 없음.
- **백엔드**: Flask `api_server.py` — 서무비서 API, 내규 원문·서식 제공, 내규 업로드.
- **배포**: Vercel (`api/index.py`가 Python 서버리스 진입점, 정적 파일은 `index.html`·`upload.html`·`regulations/`·`assets/`)

### 로컬 실행
```bash
pip install -r requirements.txt
python run_local.py          # http://localhost:5100 (PORT 환경변수로 변경 가능)
```

### 배포
- `main` 브랜치에 병합하면 Vercel이 **자동으로 배포**합니다. PR마다 미리보기(Preview) 주소가 생성됩니다.
- 환경변수는 Vercel 프로젝트 설정 → Environment Variables에서 등록합니다(예시: `.env.example`). **키·토큰은 코드나 저장소에 넣지 마세요.**
- 기관 내부 서버에서는 `Dockerfile`로 실행합니다([docs/ADOPTION.md](docs/ADOPTION.md#1-설치)).

### 환경변수

| 이름 | 용도 | 필수 |
|---|---|---|
| `REG_UPLOAD_TOKEN` | 내규 업로드·기관 절차·기관 설정 저장용 관리자 토큰 | 관리 기능 사용 시 |
| `SECRETARY_CONFIG` | 기관 설정 파일 위치(기본 `secretary/config.json`) | 선택 |
| `GITHUB_TOKEN`, `GITHUB_REPO`, `GITHUB_BRANCH` | 읽기 전용 배포에서 업로드·기관 절차를 저장소에 커밋 | 관리 기능 사용 시 |
| `REG_UPLOAD_MAX_MB` | 내규 업로드 최대 크기 | 선택 |
| `GEMINI_API_KEY` | 관련 조문 찾기의 의미 검색(임베딩) | 선택 |
| `SEMANTIC_MIN_SCORE` | 의미 검색 최소 유사도 | 선택 |
| `REG_PDF_BASE_URL` | 내규 원본 PDF 주소 접두어 | 선택 |
| `ALLOWED_ORIGINS` | CORS 허용 도메인 | 선택 |

### 절차 관리
- 형식은 `secretary/schema/procedures.schema.json`(절차·절차 팩), `config.schema.json`(기관 설정)에 정의돼 있습니다.
- **공통 절차**: `secretary/procedures.json`. 고친 뒤 `python scripts/stamp_procedures.py`로 근거 개정 정보를 다시 기록합니다(`--check`는 점검만). 근거는 `{"reg":"규정명","art":"조번호"}`로 적으면 화면에서 `regulations/` 원문의 해당 조문을 불러옵니다(조문 번호가 없는 지침은 `"q":"찾을 말"`). 서식은 `{"reg":"규정명","label":"별지 제N호 서식"}`.
- **기관 절차**: 화면의 **⚙ 규정·절차 관리**에서 저장 위치를 '기관'으로 고르고 저장합니다. `REG_UPLOAD_TOKEN`이 필요하고, GitHub 연동 시 `secretary/org.json`으로 커밋됩니다. 같은 id로 저장하면 공통 절차를 덮어씁니다.
- **개인 보충**: 각 사용자가 브라우저에 저장합니다. 내보내기·가져오기로 옮길 수 있습니다.
- 내규가 개정되면 근거 조문은 원문에서 자동으로 최신본이 보입니다. 기한·단계가 바뀐 경우에만 절차를 수정하세요.

### 내규 추가·개정
1. `/upload` 페이지에서 개정·신규 내규 문서를 업로드합니다(`REG_UPLOAD_TOKEN` 필요).
2. 변환된 원문은 `regulations/<규정명>/`에 저장되고, 목록은 `regulations_manifest.json`에 반영됩니다.
3. 의미 검색 색인을 다시 만들 때는 `scripts/build_embeddings.py`를 실행합니다(`GEMINI_API_KEY` 필요).

## 자주 묻는 질문
**Q. 처리 이력이나 개인 메모가 사라졌어요.**
브라우저에만 저장되므로 브라우저 데이터를 지우거나 다른 PC·브라우저를 쓰면 보이지 않습니다. 처리 이력 탭의 **⬆ 가져오기**로 백업 파일을 불러오세요.

**Q. 우리 부서만의 절차를 넣고 싶어요.**
**⚙ 규정·절차 관리 → ＋ 새 절차 만들기**에서 단계·기한·근거·서식을 입력하고 '개인'으로 저장하세요. 기관 전체에 쓰려면 관리자가 '기관'으로 저장합니다.

**Q. 다른 기관인데 그대로 쓸 수 있나요?**
네. 코드 수정 없이 기관 설정을 바꾸고, 우리 내규를 일괄 등록한 뒤, 규정명 매핑으로 절차를 우리 규정에 연결하면 됩니다. [docs/ADOPTION.md](docs/ADOPTION.md)를 따라 하세요.

**Q. 개정된 내규가 반영되지 않았어요.**
관리자가 `/upload`에서 개정본을 올려야 반영됩니다.
